# TrollLifeAI · AI 剧情接入说明

> 让大模型每年为你**原创**一条贴合当前人生的剧情事件，同时保证游戏永远不会因为网络问题卡住。

---

## 1. 它到底做了什么

```
玩家点「过一年」
   └─ 本地引擎照常推进（属性漂移 / 收入 / 抓捕 / 成瘾判定）
        └─ 抽出一条本地事件（155 条剧情池之一）
             └─ 若 AI 开启且命中概率 → 先弹「AI 正在续写剧情…」
                  ├─ 成功：用 AI 原创事件替换本地事件（弹窗带「AI 原创」标记）
                  └─ 失败 / 超时 / 结构不合格 / 玩家点「不等了」：立刻用本地事件继续
```

**关键点**：AI 只负责"写一条剧情"，**能不能落地由本地引擎说了算**。所以：
- 断网、Key 过期、接口限流 → 退化为单机游戏，**不卡死、不报错崩溃**；
- AI 返回的属性数值越界 → 自动夹取到合法范围；
- AI 少写了属性键 → 自动补 0；
- 返回的不是 JSON / 结构不对 → 整条丢弃，用本地剧情。

---

## 2. 三步接入

1. 游戏底部点 **AI** 页签
2. 填三样东西：
   - **接口地址**：默认 `https://api.deepseek.com/v1/chat/completions`（OpenAI 兼容格式，换 OpenAI / 其他网关也能用）
   - **模型名称**：默认 `deepseek-chat`
   - **API Key**：你自己的 Key
3. 点 **测试连接** → 看到「✓ 连接成功」后，把 **开启 AI 剧情** 打开即可

触发频率建议先用 **偶尔（15%）**，一局下来大概十几次请求；调到 **偶尔** 时每次大约几百到一千 token。

## 3. 安全与隐私（重要）

| 事项 | 做法 |
| --- | --- |
| Key 存在哪 | 只存在**本机 localStorage** 的独立键 `tlai_ai_v1`；`app.html` 里**没有任何 Key**（自检项会扫描 `sk-` 前缀并断言不存在） |
| 会不会随存档导出 | 不会。导出存档只包含人生状态与成就，**不含 AI 配置** |
| 会不会随代码上传到 GitHub | 不会。Key 不在任何文件里，是你运行时手输的 |
| 清空存档会删掉 Key 吗 | 不会。「清空全部存档」只清人生与成就，AI 配置保留；要清 Key 请点 **清除 Key** 按钮 |
| 请求发到哪里 | 只发到你填的那个接口地址，中间没有任何中转服务器；本项目没有后端 |

> ⚠️ 唯一要避免的事：**不要把 Key 写进 `app.html` 或任何文件后再推到公开仓库**。本项目不需要你这么做。

## 4. 它是怎么绕过 `file://` 的跨域限制的

`file://` 页面直接用 `fetch` 调外部接口会被 CORS 挡住（接口不带放行头，或一带 `Origin` 就 403）。所以壳里加了一条**纯传输**的原生通道：

```objc
// ViewController.m —— 只做传输，不解析、不判断业务
[config.userContentController addScriptMessageHandler:self name:@"nativeHttp"];
```

页面侧：

```js
// 有原生通道（App 内）→ 走 NSURLSession；没有（电脑浏览器）→ 回退 fetch
window.apiPost(url, headers, bodyText, timeout, cb)
```

回传：

```js
window.__nativeHttpResult = function (err, text, status) { /* 交给业务层解析 */ };
```

请求头与请求体原样透传（含 `Authorization: Bearer <key>`），响应文本 + HTTP 状态码回传，**JSON 解析与校验仍然在 JS 里**，壳保持"零业务"。

> 在电脑浏览器里直接双击 `app.html` 时没有原生通道，会走 `fetch`。如果目标接口不允许跨域，这一步会失败——这是浏览器的安全策略，不是游戏 bug。想验证 AI 功能请用 App 内运行，或换一个允许 CORS 的网关。

## 5. 提示词与校验规则（可自行调优）

**System 提示词**要求模型只输出一个 JSON 对象：

```json
{"title":"事件标题","story":"第二人称剧情描述","choices":[
  {"option_text":"选项","desc":"结果说明",
   "attr_change":{"智力":0,"体质":0,"魅力":0,"财富":0,"快乐":0,"运气":0,
                  "健康值":0,"成瘾值":0,"名声值":0,"压力值":0,"罪恶值":0}}]}
```

并强制：11 个键齐全、整数、除财富外 ±15（财富 ±30000）、成瘾值/罪恶值 0~20、标题≤18 字、选项 2–3 个且有取舍、`desc` 可选地追加剧情标记（`【习得:programming】`、`【关系:spouse:小雨】`、`【入狱:3】` 等）。

**User 提示词**会带上当前状态：年龄、年代、城市、职业与月薪、11 项属性、已习得技能、重要关系（含好感度）、宠物、成瘾情况，以及**最近 14 条已发生剧情的标题**（避免重复），并按年龄段追加口吻要求（幼儿/学生/老年）。

**本地校验（`TL.ai.normalizeEvent`）**：
- 标题/剧情为空 → 丢弃
- 选项 0 个 → 丢弃
- 属性缺键 → 补 0；小数 → 四舍五入；越界 → 夹取
- `option_text` 为空 → 跳过该选项
- 通过后统一变成与 `event.json` **完全同构**的对象，直接进入现有事件结算管线（含标记解析）

## 6. 成本与用量控制

| 机制 | 说明 |
| --- | --- |
| 触发概率 | 「偶尔 15% / 经常 35% / 每年 100%」三档 |
| 每世上限 | 默认 30 次，到顶自动停用（本世内） |
| 起始年龄 | 默认 6 岁，童年留给内置剧情 |
| 超时 | 默认 45 秒，超时立即回退 |
| 失败统计 | AI 页显示本世"失败次数"，方便判断 Key/额度是否异常 |
| 剧情缓存 | 本世 AI 原创剧情标题列表保留在存档里，可回看 |

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 测试连接报 `401` | Key 错或没余额；到服务商控制台确认 |
| 测试连接报 `404` | 接口地址不对，注意要带 `/v1/chat/completions` 或服务商要求的完整路径 |
| 报 `model not found` | 模型名写错（DeepSeek 常用 `deepseek-chat`） |
| 连接超时 | 网络问题；把超时调大到 60000，或换网络 |
| 一直"AI 未成功…已改用本地剧情" | 看 AI 页的失败次数与提示文字：多为 Key/额度/跨域（浏览器环境）问题 |
| 生成内容不合口味 | 直接改 `app.html` 里 `TL.ai.SYSTEM` 提示词后重新构建，或降低触发频率 |
| 想彻底关掉 | AI 页点「清除 Key」或把开关关掉，游戏回到纯单机 |
