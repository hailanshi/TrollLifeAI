# TrollLifeAI · 打开闪退排查手册

> App 里已经内置了崩溃日志与自诊断。按下面的顺序走一遍，基本一定能定位到原因。

---

## 0. 实战记录：第一版「打开即闪退」的真实原因（已修复）

**症状**：TrollStore 正常安装、图标正常、点开就闪退（iOS 15.1 / iPhone 13,4）。

**日志证据**（诊断版捕捉到的）：

```
[03:48:42.787] ● 阶段: 开始查找 index.html
[03:48:42.788] ‼️ 创建 WKWebView 抛异常: NSInvalidArgumentException
                *** -[__NSArrayM insertObject:atIndex:]: object cannot be nil
```

**根因**（壳代码的 bug，与 iOS 版本无关）：

```objc
// ❌ 错误写法：pathForResource: 找不到资源时返回 nil，
//           而 NSMutableArray 的 addObject: 传 nil 会立刻抛 NSInvalidArgumentException
[candidates addObject:[[NSBundle mainBundle] pathForResource:@"index" ofType:@"html" inDirectory:@"Resources"]];
```

包内只有 `index.html` 与 `www/index.html`，**没有** `Resources/index.html`，所以第三个候选返回 `nil` → 抛异常。
第一版没有 `@try/@catch`，异常冲出 runloop → **App 直接闪退**；
诊断版因为包了 try-catch，才把它抓住并显示成诊断页（这也是为什么诊断页里会写「Resources/index.html 缺失」）。

**修复**（现在代码里已是这样，并且加了自检规则防回归）：

```objc
// ✅ 正确写法：先判空再添加
NSString *p1 = [[NSBundle mainBundle] pathForResource:@"index" ofType:@"html"];
NSString *p2 = [[NSBundle mainBundle] pathForResource:@"index" ofType:@"html" inDirectory:@"www"];
NSString *p3 = [[NSBundle mainBundle] pathForResource:@"index" ofType:@"html" inDirectory:@"Resources"];
if (p1.length > 0) { [candidates addObject:p1]; }
if (p2.length > 0) { [candidates addObject:p2]; }
if (p3.length > 0) { [candidates addObject:p3]; }
```

**经验**：ObjC 里凡是 `pathForResource:` / `objectForKey:` / `dictionaryWithContentsOfFile:` 这类**可能返回 nil** 的 API，
返回值都不能直接塞进 `NSMutableArray`/`NSMutableDictionary`。`tools/selfcheck.js` 现在会扫描并拦截这种写法。

### 修复后第一次打开，如果看到的是诊断页怎么办？

因为之前闪退过几次，App 会把「连续启动失败」记下来；**连续 2 次失败会自动进安全模式**，于是第一屏就是诊断页。
这是正常的自愈逻辑，不是又坏了。点诊断页里的任一按钮即可：

- **「③ 加载正式页」**（推荐）或 **「重试打开网页」** → 页面加载成功后会**自动退出安全模式**，直接进入游戏
- 之后每次打开都会直接进游戏（日志里会出现 `✅ 启动完成（阶段 ready）`）

如果点完还是出问题，点 **「复制报告」** 把报告发我即可。

## 1. 三条拿到日志的路（任选，越靠前越省事）
### ① App 里的「诊断」按钮（推荐）
App 右上角有一个半透明小按钮 **「诊断」**。点它就能看到完整报告：

- 设备型号 / 系统版本 / 机型标识
- App 版本、Bundle ID、可执行文件、Bundle 路径
- **启动面包屑**（从进程启动到页面加载完成的每一步，带时间戳）
- 内置资源检查：`index.html` 是否存在、多大
- 日志文件尾部内容

页面底部有三个按钮：**「重试打开网页」「复制报告」「清空日志」**。

### ② 安全模式（连续两次启动失败会自动进入）
如果上一次启动**没有走完**，下次启动就会自动进入安全模式：**完全不创建 WKWebView**，
直接显示上面那份纯 UIKit 诊断页。这样即使崩溃原因就在 WebKit 里，你也一定能看到屏幕上的信息。

> 也就是说：**如果第一次闪退，第二次打开就一定会停在诊断页**（而不是又闪退）。

### ③ 「文件」App 里取原始日志（最完整）
```
「文件」App → 浏览 → 我的 iPhone → TrollLifeAI → crash.log
```
（因为 `Info.plist` 开了 `UIFileSharingEnabled`，这个目录在手机上直接可见，不需要电脑。）

## 2. 日志里怎么看"崩在哪"

日志里每一行 `● 阶段: xxx` 都是走过的一步。**最后一条阶段记录，就是崩溃前最后到达的地方**。

| 最后停在的阶段 | 说明崩溃发生在 |
| --- | --- |
| `main() 进入` | 进程刚起来就崩 → 基本是 **dyld / 系统层面**（见第 3 节） |
| `即将 UIApplicationMain(...)` | 加载 App 类时崩 |
| `AppDelegate didFinishLaunching 开始` | 启动回调里崩 |
| `UIWindow 已创建` / `根控制器已创建` | 窗口/控制器初始化 |
| `ViewController.viewDidLoad 进入` | 控制器开始构建 |
| `WKWebViewConfiguration 创建完成` | WebKit 配置 |
| `原生通道 ... 注册完成` | 脚本消息通道注册 |
| `WKWebView 实例创建完成` | WebView 实例化 |
| `scrollView 缩放与安全区设置完成` | 滚动视图设置 |
| `WKWebView 已加入视图层级` | 加入视图树 |
| `调用 loadFileURL 加载页面` | 页面加载调用 |
| `页面加载完成 didFinishNavigation` | 页面已加载，随后是白屏检测 |
| `页面 DOM 长度 = N` | `N=0` 说明**白屏**（页面没渲染出来） |
| `✅ 启动完成（阶段 ready）` | 一切正常 |

另外这些记录有专门含义：

- `‼️ 检测到上次启动未完成（停在阶段：xxx）` —— 上次崩溃点
- `===== 信号崩溃 signal=11 (Segmentation fault) 阶段=xxx =====` + 调用栈 —— 内存类崩溃
- `===== 未捕获异常 =====` + 名称/原因/调用栈 —— Objective-C 异常
- `⚠️ WebContent 进程被终止` —— 网页进程被系统杀掉（内存不足）

## 3. 如果日志里什么都没有（连 `main() 进入` 都没有）

说明 **我们的代码一行都没跑到**，属于下面这几类：

1. **签名 / 安装问题**：TrollStore 没正确签名（重装一次，或换 TrollStore 的「用 ldid 签名」选项）
2. **系统版本不支持**：TrollStore 的官方支持范围是 **iOS 14.0 – 17.0**。低于 14 装不上，高于 17 需要特定版本的 TrollStore 分支
3. **dyld 加载失败**：需要系统级崩溃报告

### 拿系统级崩溃报告（唯一能查这类问题的方式）
```
设置 → 隐私与安全性 → 分析与改进 → 分析数据
→ 找名字以 TrollLifeApp 开头的 .ips 文件（按时间排最新的那个）→ 分享出来
```
这份 `.ips` 里有 `Exception Type`、`Termination Reason`、以及 dyld 的加载错误，是最权威的证据。

## 4. 已知容易踩的坑（这次已经全部处理）

| 症状 | 原因 | 状态 |
| --- | --- | --- |
| iOS 12/13.0–13.3 上启动即崩 | 二进制用了 chained fixups，dyld 加载不了 | ✅ 已用脚本验证：本包走 `LC_DYLD_INFO_ONLY`，**没有**用 chained fixups |
| 装完闪退且无任何界面 | 包是"空壳"（主程序没编出来） | ✅ CI 强制 `test -f 主程序`，且我本地验过主程序是 arm64 Mach-O |
| 打开全白 | `index.html` 没进包 / 路径不对 | ✅ 包内有 `index.html` 与 `www/index.html` 双份；壳按三个候选路径查找；加载后还会做 DOM 长度白屏检测 |
| iPad 上装了但疑似兼容问题 | `UIDeviceFamily` 被 Xcode 覆盖成 `[1,2]` | ✅ 已在 target 级显式设为 `[1]` |
| 点按钮没反应 | WKWebView 下动态绑定事件失效 | ✅ 全部内联 `onclick` + 函数挂 `window`（自检项） |
| 图标空白/透明 | 图标带 Alpha 通道 | ✅ 图标为 24bpp 无 Alpha 通道 |
